Configuración del sistema

WebSocket, tareas programadas y permisos.

Elegir el tipo de conexión

En Administración del sitio → Extensiones → Módulos de actividad, abre la configuración de KUET. El documento original identifica esta pantalla como «Jam QuizShow».

El servidor WebSocket sincroniza las sesiones manuales de una única plataforma Moodle. Los navegadores se conectan mediante WSS. Si el servidor no está disponible, no se puede entrar en esas sesiones.

Sin socket

Selecciona «No usar socket» si solo necesitas sesiones programadas. No requiere más configuración de conexión y los modos manuales no estarán disponibles al crear sesiones.

WebSocket local

Se ejecuta en el mismo servidor que Moodle y KUET lo inicia automáticamente cuando hace falta.

  • Puerto: un puerto abierto, 8080 por defecto.
  • Certificado: certificado SSL válido para el servidor, en formato .crt o .pem.
  • Clave privada: clave correspondiente en formato .pem o .key.

WebSocket externo

Configura la URL externa con HTTPS y el puerto abierto del servidor, 8080 por defecto.

  1. Descarga unimoodleservercli.php desde la configuración de KUET y súbelo al servidor elegido.
  2. Prepara el certificado y la clave privada, y anota sus rutas absolutas.
  3. Ejecuta php unimoodleservercli.php en la terminal del servidor.
  4. Introduce el puerto y las rutas absolutas del certificado y la clave cuando se soliciten.

El usuario que ejecuta el proceso necesita permiso de lectura de ambos archivos. El administrador debe supervisar la disponibilidad del servicio y puede monitorizarlo o detenerlo como cualquier otro proceso.

Certificados y test de conexión

La conexión local y la externa requieren un certificado SSL y su clave privada válidos para el servidor y aceptados por los navegadores. Guarda la configuración y utiliza el enlace de test de conexión para comprobar que el socket está funcionando y admite conexiones seguras.

Tarea programada

En Administración del sitio → Servidor → Tareas → Tareas programadas encontrarás mod_kuet\task\active_session_management. Por defecto se ejecuta cada minuto y abre o cierra las sesiones con fechas configuradas. Deshabilitarla o espaciar demasiado su ejecución puede retrasar esos cambios.

Permisos y capacidades

  • mod/kuet:addinstance: crear y configurar actividades; profesor editor y gestor, en el contexto del curso.
  • mod/kuet:view: acceder a la actividad; estudiantes, profesores, profesores editores y gestores.
  • mod/kuet:managesessions: crear, editar y eliminar sesiones; profesores y gestores.
  • mod/kuet:startsession: iniciar y finalizar sesiones; profesores y gestores.
  • mod/kuet:viewanonymousanswers: ver respuestas marcadas como anónimas en informes; asignada por defecto al arquetipo gestor.

Salvo addinstance, estas capacidades utilizan el contexto del módulo. Revisa las asignaciones si utilizas roles personalizados.
